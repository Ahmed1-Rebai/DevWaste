DevWaste AI: how it works

Deep-learning anomaly detection for Docker. 100% local, no LLMs, diagnostic only.

1

Collect devwaste collect

Read-only Docker stats, computed like docker stats: CPU %, memory %, network rx/tx, block read/write. Stored locally in SQLite.

2

Prepare

Counters become per-interval deltas. Chronological split per container, scaler fit on training data only, sliding windows of 10 samples. No data leakage.

3

Learn normal devwaste train

LSTM autoencoder in PyTorch, trained on normal windows only. Threshold = 95th percentile of validation reconstruction error (or EVT).

4

Monitor live devwaste monitor

Each container's latest window is reconstructed. Error above the threshold for N consecutive windows → ALERT, plus the feature that drove it.

5

Report evaluate · report · cleanup --dry-run

Terminal tables, JSON / JSONL, an offline HTML report. Cleanup tips are suggestions only: DevWaste never stops or deletes anything.

REAL RUN5 containers (Postgres, Redpanda, Redis, MLflow, Dagster), ~8 s CPU training. During a redis-benchmark spike, only flakeradar-redis-1 was flagged: score 13.4 → 83.2 (threshold 3.29), driver cpu_percent.
